# Adaptive QKD Key Management — research dashboard

A three-page local Streamlit application over the framework in
`main-model-18-09-2026.ipynb`, for the research

> **An AI-Assisted Adaptive Key Management Framework for QKD-Enabled End-to-End
> Secure Communication.**

**Research prototype — simulated QKD.** There is no physical laser, fibre,
detector or hardware telemetry anywhere in this system, and no fibre distance is
modelled.

Run these from the folder that contains `app.py`.

```powershell

python -m pytest -m "not slow"
```

It opens at <http://127.0.0.1:8501>. `.streamlit/config.toml` binds the server to

Linux/macOS is the same with `python3 -m venv .venv && source .venv/bin/activate`.

## 2. Where artifact and data paths live

**One place: `dashboard/config.py`.** Nothing else in the codebase hard-codes a
path, a threshold or a confidence level, and no developer or Kaggle path appears
anywhere. Override any field without editing code, either with an environment
variable `QKDDASH_<FIELD>` or with a `dashboard_config.toml` next to `app.py`:

```toml
nids_artifacts_dir = "D:/CAMPUS/.../nids_artifacts"
qkd_detector_artifact = "D:/CAMPUS/.../qkd_anomaly_detector.joblib"
```

| Config field | What it expects | If absent |
|---|---|---|
| `nids_artifacts_dir` | the export from `nids-model-15-09-2026.ipynb`: `nids_inference_bundle.joblib`, `nids_run_metadata.json`, `nids_artifact_manifest.json`, `network_feature_pool.csv` | network signal **Unavailable**, QKD-only fallback |
| `qkd_detector_artifact` | joblib export of a trained `QKDAnomalyDetector` | stated observed-QBER heuristic, labelled as such |
| `pool_forecaster_artifact` | joblib export of a fitted `PoolDemandForecaster` | linear-trend depletion estimate, labelled as such |
| `fusion_weights_artifact` | JSON `{"w_qkd": <0..1>}` from Step 7C | QKD-only fusion mode |
| `baseline_summary_artifact` | a CSV the notebook already produced | the baseline expander says so and computes nothing |

The default location for all of them is `artifacts/`, which ships empty. **The
app opens and works with none of them present** — it simply states which signals
are unavailable.

## 3. Architecture

```
app.py                     page shell, navigation, one runtime per browser session
dashboard/config.py        every path, bound and threshold
dashboard/adapter.py       THE integration surface the UI talks to
dashboard/theme.py         header / cards / badges
dashboard/views/           overview.py, session_monitor.py, key_pool.py  (rendering only)
dashboard/runtime/
    notebook_runtime.py    GENERATED - definitions extracted from the notebook
    secure_messaging.py    hardened AEAD envelope over the framework's key delivery
    risk.py                risk inputs, each with explicit provenance
tools/extract_runtime.py   regenerates notebook_runtime.py
tests/                     31 tests (see §7)
```

UI rendering is strictly separated from simulation, policy and cryptography: the
views call the adapter and never import `notebook_runtime`.

The adapter exposes exactly the required surface: system status, QKD session
execution, telemetry snapshots, AI decision evaluation, key-pool summaries,
lifecycle records, secure send/receive, controlled tampering, simulation reset
and sanitised event export.

### Control-plane wiring

The key pool, lifecycle manager, key-delivery API, rekeying command interface
and the Alice/Bob secure channel all share **one runtime and one connection id**
(`alice<->bob`). That is deliberate: in the notebook the rekeying interface uses
a separate `ai-control-plane` connection, so an AI rekey could not affect the key
the communication demo used. Here it does, and `tests/test_control_plane.py`
asserts it.

### Runtime changes made at the dashboard layer (documented, tested)

These are **additions in dashboard code**, not edits to the notebook. The
notebook's own published results were not produced with them:

1. **Bound AAD.** The notebook authenticates a constant `b'qkd-e2e'`. The
   dashboard's envelope authenticates connection id, key id, sequence number and
   algorithm.
2. **Replay protection.** AES-GCM accepts a valid envelope any number of times;
   a `(key_id, seq)` receive ledger rejects the second delivery.
3. **Lifecycle re-validation at use time.** The notebook's receiver caches key
   bytes by `key_id` and never re-checks state, so a cached key keeps decrypting
   after revocation or expiry. Every send and receive here re-reads the record.
4. **Nonce ledger surviving reset.** Process-scoped, deliberately not cleared by
   "Reset Simulation".
5. **Channel-preserving replenishment.** `KeyLifecycleManager._default_replenish`
   hard-codes `eve_rate=0.0`. The dashboard replaces it with a replenisher bound
   to the configured channel, so an eavesdropper is never silently switched off
   to make key generation succeed.
6. **Control-plane key registration.** `RekeyingCommandInterface` calls the
   lifecycle manager directly, so the delivery API never sees the resulting
   `key_id` and the responder would refuse it. The adapter registers the id on
   the same connection; it grants no new capability.

## 6. Demonstration sequence

1. **QKD Session Monitor** → leave the defaults (2000 photons, 2 % depolarising,
   Eve off) → **Run session**. Stages complete through Admission to key pool;
   the session is accepted and secret bits enter the pool.
2. **Key Pool and Lifecycle** → **Send securely**. A key is requested, the
   message is encrypted with AES-256-GCM, delivered and decrypted. One outcome:
   `DELIVERED`.
3. **QKD Session Monitor** → tick **Enable simulated eavesdropper** (0.30) →
   **Run session**. The QBER rises, the 99 % upper bound crosses 11 %, the
   session **aborts**, and nothing is admitted to the pool.
4. **Overview** → the fused risk score is at its ceiling, the decision is
   `REKEY_NOW`, and the execution outcome shows whether a key was actually
   issued. If the pool cannot fund one, the state is blocked/pending — rekeying
   does not remove the eavesdropper.
5. **QKD Session Monitor** → untick the eavesdropper → **Run session**.
   Acceptable material is produced again and a verified key becomes available.
6. **Key Pool and Lifecycle** → **Send securely** → `DELIVERED` under the new
   key. Then **Tamper before delivery** → `INTEGRITY_FAILURE`, and **Replay the
   last delivered envelope** → `REPLAY_REJECTED`.

Screenshots of this run are in `docs/screenshots/` (captured from a real browser
session; none are mocked).

## 8. Security and trust boundary

- **Local Alice/Bob encryption demonstration; the dashboard server is within the
  trusted boundary.** Both logical endpoints run in one Python process, so the
  server does see plaintext. This is *not* browser-to-browser end-to-end
  encryption, and the app says so on the page.
- The server binds to `127.0.0.1`. No external hosting, no tunnel.
- All user-entered text is HTML-escaped before rendering; messages are capped at
  2048 bytes.
- No raw key material is displayed, logged or exported. The JSON export carries
  key ids, lengths, states, timestamps, decisions and outcomes only, and passes
  through a redaction pass on the way out.
- Key destruction overwrites the numpy buffer in place before dropping the
  reference. That is **best effort in CPython** and is described as such — no
  claim of guaranteed secure erasure from process memory is made.
- Randomness for the simulation is seeded numpy PCG64 — reproducible and
  explicitly **not cryptographic**. The keys produced here are reproducible
  simulation artefacts, as the notebook already states.

## 9. What is implemented, tested, untested and unavailable

**Implemented and tested**

- Three pages, session-state runtime, non-mutating redraw.
- Real simulated BB84 with QBER upper-bound abort, Wegman–Carter classical
  authentication, Cascade, key verification, Toeplitz privacy amplification.
- Key pool, lifecycle state machine, ETSI-style key delivery.
- Real AES-256-GCM with a bound AAD envelope, replay protection, nonce ledger,
  lifecycle re-validation, and a genuine tamper test.
- Control-plane integration: an AI rekey changes the application's key.
- Channel-preserving, bounded replenishment.
- Explicit QKD-only fallback when the network model is missing or rejected.
- Sanitised export.

**Implemented but not exercised in this build**

- The *trained* QKD anomaly detector path, the *fitted* forecaster path and
  *weighted* fusion. The loaders, schema checks and refusal paths are written and
  tested with negative fixtures, but no such artifacts were available, so the
  positive paths have never run against a real export.
- The `NIDSThreatAdapter` positive path (a reliable bundle). Its refusal paths
  are tested; its scoring path is not, for the same reason.

**Not implemented**

- Live packet capture (not required; recorded replay is used instead, labelled).
- Distributed Alice/Bob endpoints, user accounts, persistence across restarts.
- Decoy states, photon loss sweeps, fibre or detector physics.
- Any finite-key security proof for the produced bits.

**Unavailable in this environment**

- `nids_artifacts_dir` is empty, so the network signal is **Missing** and the
  app runs QKD-only. Point the config at the NIDS export to enable it.
- No trained `QKDAnomalyDetector` was exported by the notebook, so the QKD
  anomaly signal uses the **stated observed-QBER heuristic**:
  `score = clip(QBER_upper_bound / QBER_abort_threshold, 0, 1)`. It is monotone
  in the quantity the protocol already decides on, it is reproducible, and it is
  **not a probability and not a model output**. Because it is not a probability,
  the notebook's cost-derived probability thresholds are *not* reused with it;
  the app uses separate, stated bands (0.45 / 0.65 / 0.85) and displays that
  provenance next to every decision. Export a detector and the app switches to
  the trained score and the cost-derived thresholds automatically.
- No fusion weights were exported, so fusion mode is `QKD_ONLY` and the fused
  score *is* the QKD anomaly score. The network signal, when available, is shown
  as a separate input and is not silently blended in.

**This dashboard running does not mean the research, the security argument or
the thesis is complete.** It is an interface over the framework, with the
framework's own limitations intact.
